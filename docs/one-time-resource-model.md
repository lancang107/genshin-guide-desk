# 一次性资源库设计

## 结论

可行，但第一版不应逐个录入所有宝箱。资源库应该以“可推荐且可检查完成状态的任务批次”为最小单位：主线按章节、世界任务按任务线、宝箱和神瞳按区域路线批次、成就按成就组。只有拥有明确路线和完成检查点的高价值内容，再细化到单个物品。

这个资源库是跨版本的永久目录。`data/versions/{version}/primogems.json` 只保存当期内容，不能承担新玩家的历史资源统计。

## 数据边界

| 数据 | 位置 | 是否随版本覆盖 |
|---|---|---|
| 游戏内一次性资源目录 | `data/catalog/one-time-resources/` | 否，只增补和勘误 |
| 证据与来源记录 | `data/catalog/evidence/` | 否，保留核验历史 |
| 当期卡池和限时收益 | `data/versions/{version}/` | 是，按版本更新 |
| 用户完成进度 | 浏览器 localStorage，后续账号数据库 | 否，按账号保存 |

静态目录使用 `one-time-resource.schema.json`；用户状态使用 `user-resource-progress.schema.json`。用户状态不写回公共目录，避免一个账号的进度影响其他玩家。

## 单条资源模型

每条资源记录必须包含：

- `kind`：主线、世界任务、宝箱路线、神瞳路线、成就组、供奉系统等。
- `countryId`、`areaId`、可选的 `subregionId` 与 `versionIntroduced`：国家、国家下的大区/自治区域、地图子区域分层保存。`regionId` 仅作为旧数据兼容字段，不能再同时承担国家和地图区域两个含义。
- `geographyStatus`：宝箱和神瞳路线只有匹配到官方地图的 `subregionId` 后才能标为 `confirmed` 并进入自动推荐；视频中的版本简称、UP 主自定义分段和“一条龙”标题写入 `sourceLabels`，绝不作为地理字段。
- `rewards`：原石、纠缠之缘、相遇之缘、印记分开记录。印记通过 `rewardMethod: indirect-offering` 关联到供奉系统，不能直接假定等价原石。
- `estimatedMinutes`：最短、典型、上限三档。攻略视频长度只能作为辅助证据，不等同于玩家完成耗时。
- `prerequisiteIds`：任务、区域或系统的前置依赖，构成有向无环图。
- `completionGranularity`：资源本身、区域批次或单个物品。首期宝箱和神瞳使用 `batch`。
- `verification`：状态、证据 ID 和核验日期。没有证据的数字只能标为 `pending`，不进入保证资源。
- `guideLinks`：执行攻略链接。创作者链接必须来自 `data/creators.json` 的 UP 主池，并通过 `publisherVerification` 确认是创作者本人投稿；官方/米游社链接只作为核验来源。

## 推荐计算

```text
score = rewardValue / typicalMinutes
      * confidenceWeight
      * accessibilityWeight
      * deadlineWeight
```

- `rewardValue` 只使用原石与可用于限定池的纠缠之缘；相遇之缘单列展示。
- `confidenceWeight`：已确认大于估算，大于待确认。
- `accessibilityWeight`：前置已满足、练度要求低、路线清晰的任务更高。
- `deadlineWeight`：只作用于限时内容。永久一次性资源不因版本结束失效。

套餐保存策略条件，例如每日可玩时间、目标资源、排除已完成项。实际任务列表由资源目录、当前版本信息和用户进度实时生成。

## 地理层级

永久资源目录使用以下层级：

```text
国家（country）
└── 大区 / 自治区域 / 特殊地图（area）
    └── 地图子区域（subregion）
        └── 地点 / 功能区域（poi）
```

7.0 当前录入内容使用以下归属。尚未精确定位的任务、供奉与成就不以名称推断子区域，保留在其已核验的 area 下，等待补充地点证据。

```text
至冬（countryId: snezhnaya）
├── 挪德卡莱（areaId: nod-krai，自治区域）
│   ├── 帕哈岛、希汐岛、伦波岛
│   ├── 虚海望、逐浪野
│   └── 杜南纳深坑、烟硌山峰
└── 至冬本土（areaId: snezhnaya-mainland）
    ├── 焰羽谷、古兽冰原、霜殛寒峰
    └── 永凝冻土、白桦雪葬地
```

挪德卡莱属于至冬国家范围内的独立大区/自治区域，不是独立国家。特殊地区的国家归属固定为：渊下宫归稻妻、层岩巨渊·地下矿区归璃月、旧日之海归枫丹、远古圣山归纳塔、空之神殿归蒙德、挪德卡莱与霜月归至冬。后续若官方数据将某个区域提升为独立国家或新增更细的地图层级，只新增或调整地理索引，不修改资源 ID 的历史含义。

枫丹的官方地图子区域通常同时包含水上和水下空间，例如同一宝箱路线可能跨越两种移动环境。因此水上/水下暂不作为 `area` 或 `subregion` 层级；后续若攻略筛选确有需要，将新增路线维度（如 `environment: ["surface", "underwater"]`），不改变地理 ID。

## 采集与核验

1. 官方网站、官方公告和米游社官方板块：版本开放、活动期限、任务开放条件和直接奖励。
2. 米游社攻略和可信 UP 主：路线、宝箱/神瞳批次数量、典型耗时和隐藏前置。
3. 外部信息先进入证据记录，再由编辑写入资源目录。
4. 自动流程只发现新公告和新视频，输出待审核变更，不得直接覆盖线上数据。
5. 审核后执行 Schema、依赖图和奖励汇总检查，再发布。

你的影月月的视频适合提供区域批次、路线入口和时长参考；时长需要结合暂停、战斗、解谜与前置修正，保留为时间区间。

## 实施拆分

### A. 目录基础

1. 建立地区、版本、资源类型和证据目录。
2. 录入全部魔神任务、世界任务线、传说任务和邀约，并补齐依赖关系。
3. 为每条任务线记录直接奖励、典型耗时和官方/米游社证据。

产物：可查询、可排序的永久任务资源目录。

### B. 区域探索批次

1. 每个地区拆为可独立完成的宝箱与神瞳路线批次。
2. 用高质量路线视频或地图资料填写批次数量、路线和时间区间。
3. 将印记、神瞳连接到七天神像、聚所纪事和其他供奉系统；至冬 7.0 的聚所纪事按其一、其二、其三独立记录。

产物：按性价比推荐的区域探索清单，不要求逐宝箱定位。

### C. 成就与细化

1. 按成就集录入，区分自然完成和需要刻意操作的成就。
2. 为高收益或争议资源增加子任务和完成检查点。
3. 记录版本修订、地图扩展和遗漏勘误历史。

产物：可从用户已完成项中精确排除资源。

### D. 用户进度与推荐

1. 首版用 localStorage 保存状态。
2. 账号功能上线后迁移到用户资源进度表。
3. 根据剩余卡池时间、每日可玩时间、前置完成度和性价比生成动态清单。

产物：用户每次回来都从下一个未完成且最值得做的资源继续。

## ego-lite 的定位

已验证 `ego-browser` 能打开原神官网和米游社，并提取动态页面文本和链接。它适合作为内部采集流程的浏览器适配层，尤其适合米游社和人工复核页面。

它不应成为网站线上 API，也不应在未经审核的情况下改写数据。建议它输出待审核 JSON，再由校验脚本和人工确认进入版本文件。
